# LLM: text-LM обучение (byte-LM -> BPE)

## Что изменилось (по итогам аудита против nanoGPT / HF tokenizers)

1. **BPE вместо байт-фолбэка.** Раньше каждый токен = один байт (vocab=256).
   Теперь `src/atom/tok.rs`: BPE с 256 обученными слияниями на корпус
   (`train_bpe`), словарь = 256 байт + 256 merges → vocab=512.
   Декодер гарантирует байт-фолбэк: `decode(encode(x)) == x`.
   Эмбеддинг-веса сокращается с 256*d до 512*d при том же effective контексте.

2. **Train/val split.** Обучение идёт на первых 90% корпуса, валидация —
   на последних 10% (не видны обучению). Val-loss печатается каждые 25 эпох,
   лучшая модель фиксируется (`best_val`).

3. **LR-расписание.** Linear warmup (`epochs/10`, от 0 до base_lr=0.1) +
   cosine decay к ~0 (Karpathy-style). Раньше был однократный шаг
   `lr: 0.1 -> 0.02` на 60% эпох — слишком грубо.

4. **Оценка.** Val-loss считается по BPE-окнам (`avg_loss` по логитам).

## Команды

```bash
# Быстрая проверка «сеть учится» (curriculum математики, без BPE):
venv/bin/python -m atomnet.luna_mini train --backend atomnet --steps 900 --save luna-mini-900.pt

# Text-LM на своём корпусе (порядок аргументов строгий):
#   luna text <file> <epochs> <threads> <temp> <d> <blocks> <window>
cargo run --release --bin luna -- text data/persona_v3_clean.txt 200 6 0.7 96 2 128

# Увеличенный конфиг:
cargo run --release --bin luna -- text data/persona_v3_clean.txt 150 6 0.7 128 3 160
```

## Строгая валидация аргументов

`src/bin/luna.rs` не принимает «тихие» ошибки: любая опечатка или
неверное значение → понятное сообщение на stderr + код выхода 2:

| Правило | Сообщение |
|---|---|
| `epochs >= 1` | `epochs = N: должен быть >= 1` |
| `temp ∈ (0, 2]` | `temp = N: должен быть в интервале (0, 2]` |
| `d >= 16`, кратно 8 | `d = N: должен быть >= 16 и кратен 8 (d_head = d/2)` |
| `blocks >= 1` | `blocks = N: должен быть >= 1` |
| `window >= 16` | `window = N: должен быть >= 16` |
| файл существует | `файл корпуса 'X' не найден` |
| нечисловой аргумент | `epochs = 'abc': ожидалось число` |

Те же проверки дублируются в `run_text_lm` (assert!), поэтому неверные
параметры падают громко при любом вызове, а не только из CLI.

## Гейты генерации

`[luna] gates: valid_tag / non_empty / repetition=<0.45` — финальная проверка
ответа Луны (наличие `</assistant>`, непустота, анти-«эхо» повторяемость).

## Честность цифр

- BPE-сжатие: с 256 байт на токен до ~7 байт на токен на русскоязычном
  корпусе — контекстные окна становятся «смысловыми», а не байтовыми.
- Val-loss считается как средний CE по валидационным окнам (`avg_loss`
  уже усреднён по позициям — не делим ещё раз на число позиций).
- Виртуализация (ISA/NPU/deep-профили) не меняет математику: loss считается
  теми же ядрами, что и инференс.

## Диагностика качества

`run_text_lm` печатает два вида генерации:

- `LUNA (temp=...)` — ответ на мета-промпт (`<user>...кто ты?...</user>`),
  может быть out-of-distribution для корпуса;
- `corpus seed` / `corpus gen` — продолжение сида **из самого корпуса**
  (in-distribution): если модель выучила структуру, она продолжает диалог
  в том же формате (`<user>...</user><assistant>...</assistant>`).

## Лимит корпуса

`ATOMNET_TEXT_MAX_BYTES` (по умолчанию 200 000) — сколько байт корпуса
использовать. Для больших корпусов: `ATOMNET_TEXT_MAX_BYTES=700000`.
