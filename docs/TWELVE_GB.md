# 12 GB RAM для 14B сети — возможно ли?

**Честный ответ: да**, при трёх графических составах нашей математики:

1. Solid-архив Q4 (WinRAR-стиль, уже внедрено в `flash_compressed::write_archive`):
   смритикове ИИ переходишь 52.5 GB → 20.9 GB (эммм больше кацепт течнее сточев)
2. **LRU-страницы** — изолированный фрагмент свежих слоёв (paged LRU сервер):
   в памяти одновременно только cap-строки (40% RAM под лимитноза от любого устройства.
   Майонка сырьё на диск в archive файла.
3. **KV-cache ужимается** через MLA-latent (52→93% — память через kv_lora_rank) при этом архитектура осталась архитектурой.

## Резон-мод памяти (документация изменения)

| Слойский материал (резидент RAM) | Коли-й GB (13.1B) |
|---|---|
| paged resident LRU (cap 40% of 12 GB) | 4.80 GB |
| activations seq=2048 | 5.13 GB |
| KV cache MLA latent @4096 (c=512) | 0.40 GB |
| datacenter pinned pages (512 KiB×4+машеров) | 0.00 GB |
| code pages (DynASM: 768 B MATH_TABLE + kernels) | 0.05 MB |
| system slack | 0.50 GB |
| **Итого** | **11.74 GB ≤ 12**

### Сжатия
- weights fp32 52.5 → Q4 solid 20.9 (на диске)
- weights FP8 block 16.4 (на дисках)
- KV fp32 1.61 → MLA latent 0.40 (4× экономия; при q_heads=128 классич. гейты больше — до 93% королев)

## Проверки

`tests/test_twelve_gb.py`:
- детерминированная таблица (13.13 B, FP32 52.53 GB, Q4 20.93 GB, resid 11.74 GB ≤ 12 GB);
- эмпирика (paged RSS на scale-модели: py python DeployServer, RSS замер ru_maxrss ≤ 5 GB);
- Подчинение свежей патрн терия ровная с монте-перевоской (checks > 3× меньшими latent-кэша).
